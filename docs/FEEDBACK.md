# Керівництво по роботі з відгуками (Feedback Guide)

У системі `drone-alert` реалізовано повноцінний модуль двостороннього зворотного звʼязку між користувачами бота та командою розробників/адміністраторів.

Користувач пише боту через команду `/feedback`, звернення миттєво надходить у закриту робочу Telegram-групу, а адміністратор може відповісти на нього простим **Reply** (відповіддю) у групі. Бот самостійно доставляє відповідь користувачеві від свого імені, **не розкриваючи особистий акаунт розробника**.

---

## 🏗 Як це працює (Архітектура)

```
[ Користувач ]
      │
      │  /feedback -> надсилає текст або скриншот
      ▼
[ Telegram-бот (@simpledronealert_bot) ]
      │
      │  Безпечне екранування, створення тікета в SQLite
      ▼
[ Закрита адмін-група (FEEDBACK_CHAT_ID) ]
      │
      │  Адміністратор робить "Reply" на звернення
      ▼
[ Telegram-бот (@simpledronealert_bot) ]
      │
      │  Пошук адресата за ID повідомлення
      ▼
[ Користувач отримує: "💬 Відповідь розробника: ..." ]
```

1. **Збереження стану та сесії:** Команда `/feedback` переводить користувача в режим очікування введення (FSM-стан `waiting_for_feedback`).
2. **Антиспам:** Встановлено обмеження — не частіше 1 звернення на 60 секунд від одного користувача.
3. **Реєстрація тікета:** У базі даних `data/subscribers.db` (таблиця `feedback_tickets`) фіксується звʼязок між ID повідомлення в адмін-групі (`admin_message_id`) та ID чату користувача (`user_chat_id`).
4. **Приватність:** Якщо користувач виконує команду `/stop`, бот автоматично видаляє його Telegram ID зі списку отримувачів і очищає всі його звернення з бази даних.

---

## 🚀 Покрокове налаштування з самого початку

### Крок 1. Створення закритої групи в Telegram
1. У Telegram відкрийте меню та виберіть **Створити групу** (New Group).
2. Вкажіть назву групи, наприклад: `Drone Alert — Команда & Фідбек`.
3. Зробіть групу **Приватною** (Private Group). Користувачів бота сюди додавати **не потрібно** — це внутрішній робочий чат команди.

### Крок 2. Додавання бота до групи
1. Додайте вашого бота (наприклад, `@simpledronealert_bot`) до створеної групи.
2. Відкрийте налаштування групи -> **Адміністратори** (Administrators) -> **Додати адміністратора**.
3. Надайте боту права адміністратора (найважливіші права: *надсилання повідомлень*, *закріплення повідомлень* та *доступ до повідомлень*).
   > [!NOTE]
   > Якщо бот не є адміністратором групи, увімкнений за замовчуванням Group Privacy Mode у Telegram може блокувати отримання ботом повідомлень та reply від учасників групи.

### Крок 3. Отримання Chat ID групи (`FEEDBACK_CHAT_ID`)
Telegram-групи та супергрупи мають відʼємні числові ідентифікатори (для супергруп вони починаються з `-100...`).

**Як дізнатися ID групи:**
- **Спосіб А (найпростіший через бота):**
  1. Тимчасово додайте в групу будь-якого бота для визначення ID, наприклад `@RawDataBot` або `@myidbot`.
  2. У відповіді знайдіть значення поля `chat` -> `id` (наприклад, `-1004415077933`).
  3. Видаліть допоміжного бота з групи.
- **Спосіб Б (через пересилання):**
  1. Напишіть будь-яке повідомлення в створену групу.
  2. Перешліть це повідомлення боту `@getmyid_bot` або `@ShowJsonBot` в особисті повідомлення.
  3. Рядок `Forwarded from chat: -100xxxxxxxxxx` міститиме потрібний ID.

### Крок 4. Отримання особистого Telegram ID адміністраторів (`FEEDBACK_ADMIN_IDS`)
Щоб сторонні учасники групи (якщо вони там є) або випадкові акаунти не могли відповідати користувачам від імені бота, система перевіряє право відповіді за списком дозволених ID.

1. Відкрийте в Telegram бота [@userinfobot](https://t.me/userinfobot) або [@myidbot](https://t.me/myidbot).
2. Натисніть `/start`.
3. Бот поверне ваш числовий ідентифікатор, наприклад: `266181582`.
4. Якщо адміністраторів декілька, отримайте ID кожного з них.

### Крок 5. Конфігурація змінних середовища
Додайте отримані значення до файлу `.env` на сервері:

```env
# ID закритої групи для отримання відгуків
FEEDBACK_CHAT_ID=-1004415077933

# Список ID адміністраторів через кому, які мають право надсилати відповіді
FEEDBACK_ADMIN_IDS=266181582,987654321
```

Переконайтеся, що змінні передаються у контейнер у `docker-compose.yml`:
```yaml
    environment:
      - FEEDBACK_CHAT_ID=${FEEDBACK_CHAT_ID:-}
      - FEEDBACK_ADMIN_IDS=${FEEDBACK_ADMIN_IDS:-}
```

### Крок 6. Перезапуск сервісу на сервері
Застосуйте зміни, оновивши контейнер:
```bash
cd ~/if-drone-alert
docker compose up -d --build
```

Перевірте, що змінні успішно прочитано:
```bash
docker logs if-drone-alert --tail=20
```

## 📱 Практична робота з відгуками

### Як це виглядає для користувача:
1. Користувач надсилає боту команду:
   ```
   /feedback
   ```
2. Бот відповідає:
   > 💬 **Напишіть, що варто покращити, або повідомте про помилку.** Можна додати скриншот.
   > Якщо знадобиться уточнення, відповідь розробника надійде сюди.
   > 
   > Скасувати: /cancel
   > 
   > _Це форма технічного зворотного звʼязку, а не канал екстреної допомоги._
3. Користувач пише свій текст або додає скриншот:
   > *«У районі Нової Ушиці тривога була оголошена раніше, ніж прийшло сповіщення.»*
4. Бот підтверджує отримання:
   > ✅ **Дякуємо за відгук!** Ваше звернення #1 передано розробнику.
   > Якщо знадобиться уточнення, відповідь надійде в цей чат.

---

### Де знайти надісланий відгук:
Відгук негайно зʼявляється в закритій групі `FEEDBACK_CHAT_ID`:

```text
💬 Звернення від Іван Тестовий (@ivan_test) (123456789):

У районі Нової Ушиці тривога була оголошена раніше, ніж прийшло сповіщення.
```
*(Якщо користувач додав фото — повідомлення надійде як фото з відповідним підписом)*.

---

### Як відповісти на звернення:
1. У закритій адмін-групі знайдіть повідомлення зі зверненням.
2. Натисніть на ньому правою кнопкою миші (або змахніть) та виберіть **Відповісти (Reply)**.
3. Введіть текст відповіді або додайте зображення, наприклад:
   > *«Дякуємо за інформацію! Перевірили таймінги поста в каналі, коригуємо коефіцієнт затримки.»*
4. Надішліть повідомлення в групу.
5. Бот автоматично:
   - Надішле користувачеві в особистий чат:
     > 💬 **Відповідь розробника:**
     > 
     > Дякуємо за інформацію! Перевірили таймінги поста в каналі, коригуємо коефіцієнт затримки.
   - У групі надішле підтвердження:
     > ✅ Відповідь успішно доставлено користувачеві.

## 🗄 Структура бази даних звернень

Усі звернення зберігаються в базі SQLite (`data/subscribers.db`):

```sql
CREATE TABLE feedback_tickets (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    ticket_id INTEGER,
    user_chat_id INTEGER NOT NULL,
    user_message_id INTEGER NOT NULL,
    admin_message_id INTEGER NOT NULL UNIQUE,
    created_at_utc TEXT NOT NULL,
    status TEXT DEFAULT 'open'
);
```

- `ticket_id` — порядковий номер звернення (показується користувачу).
- `user_chat_id` — Telegram ID користувача, куди доставляти відповіді.
- `admin_message_id` — ID повідомлення в адмін-групі, на яке робиться reply.
- При надсиланні нових відповідей у тій самій гілці бот привʼязує додаткові повідомлення до наявного тікета (`link_additional_admin_message`).

## 🔍 Часті питання та вирішення проблем (Troubleshooting)

### 1. Користувач отримує: «⚠️ Сервіс зворотного звʼязку тимчасово ненастроєний»
- **Причина:** Змінна `FEEDBACK_CHAT_ID` порожня або відсутня в `.env`.
- **Рішення:** Додайте `FEEDBACK_CHAT_ID` до файлу `.env` на сервері та перезапустіть контейнер.

### 2. Користувач отримує: «⚠️ Не вдалося доставити відгук через технічну помилку»
- **Причина:** Бот не може надіслати повідомлення в групу. Найчастіше:
  - Бот ще **не доданий** до групи.
  - Бота видалили або заблокували в групі.
  - Неправильно вказано `FEEDBACK_CHAT_ID` (пропущено мінус або префікс `-100`).
- **Рішення:** Перевірте наявність бота серед учасників групи та правильність ID у `.env`. Перевірте логи:
  ```bash
  docker logs if-drone-alert --tail=50
  ```

### 3. Адмін пише reply в групі, але користувач нічого не отримує
- **Причина 1:** Ваш особистий Telegram ID не вказаний у `FEEDBACK_ADMIN_IDS`. У логах зʼявиться попередження:
  `Користувач ... не має прав для відповіді на звернення (не в FEEDBACK_ADMIN_IDS)`.
  **Рішення:** Додайте ваш числовий ID до `FEEDBACK_ADMIN_IDS` через кому.
- **Причина 2:** Відповідь надіслано не як Reply на оригінальне повідомлення тікета, а як окреме нове повідомлення в чаті.
  **Рішення:** Обовʼязково використовуйте функцію **Reply (Відповісти)** саме на повідомлення бота із заголовком «Звернення від...».
- **Причина 3:** Користувач заблокував бота або зупинив його через `/stop`.
  **Рішення:** У такому разі бот повідомить у групі: `⚠️ Не вдалося доставити відповідь користувачеві: Bot was blocked by the user`.

## 📌 Закріплене повідомлення для адмін-групи
Для зручності команди рекомендується закріпити в адмін-групі коротку інструкцію:

```text
📌 Памʼятка по роботі з фідбеком:
1. Повідомлення від користувачів приходять сюди від імені бота.
2. Щоб відповісти користувачеві — зробіть Reply на відповідне звернення.
3. Ваші особисті контакти користувач НЕ бачить (доставка йде від бота).
4. Відповідати можуть лише адміністратори з білого списку FEEDBACK_ADMIN_IDS.
```
