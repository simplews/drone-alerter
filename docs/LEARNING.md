# Механізм донавчання та оновлення довідників

Цей документ описує, як система адаптується до нових даних: уточнює таблицю ETA (діапазони часу прибуття), знаходить нові відмінки чи нові населені пункти, рахує базові ймовірності $P(\text{ІФ} \mid \text{пункт})$ та безпечно оновлює довідники без ризику поламати бойові сповіщення.

---

## 1. Архітектурні принципи

1. **Версіонування замість перезапису на льоту:**
   Кожне оновлення створює новий незмінний знімок `data/reference/vNNNN.json`. Активна версія визначається вказівником `data/reference/ACTIVE`. У будь-який момент можна переглянути різницю (`diff`), схвалити (`promote`) або миттєво відкотитися (`rollback`).
2. **Гаряче підхоплення (`Hot Reload`):**
   Клас `ActiveReferenceCache` перевіряє `ACTIVE` і підтягує нову версію без потреби перезапускати демона чи зупиняти WebSocket-з'єднання з Telegram.
3. **Пакетне перенавчання (Batch Offline), а не після кожного поста:**
   ETA не повинен стрибати посеред атаки, коли сповіщення вже надсилаються. Оновлення запускається раз на добу або вручну після завершення тривог.
4. **Заморозка під час активності (`Freeze Window`):**
   Якщо за останні 3 години є нерозмічені/живі цілі, перенавчання автоматично відкладається.
5. **Асиметрична безпека діапазонів:**
   - Поки даних мало ($n < 8$), нові спостереження можуть **лише розширювати** інтервал (об'єднання з фізичною моделлю та апріорним діапазоном).
   - Коли даних достатньо ($n \ge 8$), розрахунок ведеться за квантилями ($q_{10}$ та $q_{90}$) з відступами, але **звужувати інтервал дозволено не більше ніж на 3 хв за одне оновлення**.
   - Розширювати інтервал дозволено без обмежень (недооцінка часу небезпечніша за переоцінку).
6. **Human-in-the-loop для топонімів (захист від омонімів):**
   Жодна нова назва не додається в робочий словник автоматично. Невідомі назви збираються в чергу `alias_candidates`. Оператор через CLI переглядає контекст і вирішує: приєднати до існуючого пункту, створити новий пункт чи відхилити (стоп-слово).
7. **Безпека чутливих даних (ППО):**
   База зберігає лише факт результату (`reached_target`, `downed_en_route`, `diverted`). Точні координати збиття чи робота ППО **не збираються і не зберігаються**.

## 2. Потік даних

```
[ Пости моніторингових каналів ]
               │
               ▼
   [ store.add_post / add_mention ]
               │
      ┌────────┴───────────────────────────┐
      ▼                                    ▼
[ alias_candidates ]              [ Розмітка результатів ]
(нові форми назв)                  (reached_target, arrived_at, ...)
      │ (людина: approve/reject)           │
      ▼                                    ▼
[ Схвалені аліаси ]              [ Спостереження arrival_obs ]
      └────────────────┬───────────────────┘
                       ▼
           [ pipeline.retrain() ]
                       │
           ├── 1. Калібрування ETA & швидкості
           ├── 2. Оцінка P(ІФ | пункт)
           ├── 3. Перевірка на Holdout (найсвіжіші цілі)
           ▼
    [ Нова версія vNNNN (pending) ]
           │
           ├── Перевірки пройдені (Gate Checks)
           ▼
   [ promote -> ACTIVE -> Hot Reload ]
```

## 3. Модель калібрування ETA

Для кожного пункту $P$:
- Якщо $n = 0$: використовується фізична оцінка за відстанню $d$ до аеродрому:
  $$t_{\min} = \frac{d}{v_{\max}} \cdot 60 - \text{lag}_{\max}$$
  $$t_{\max} = \frac{d}{v_{\min}} \cdot 60 + \text{lag}_{\max}$$
  де $v \in [340, 450]\text{ км/год}$, $\text{lag} \in [1, 3]\text{ хв}$.
- Якщо $n < 8$: $\min(\text{спостережень}) - 2\text{ хв}$, $\max(\text{спостережень}) + 2\text{ хв}$, об'єднані з попереднім діапазоном і фізичною оцінкою.
- Якщо $n \ge 8$: емпіричні квантилі $Q(0.10) - 2\text{ хв}$ та $Q(0.90) + 2\text{ хв}$ з обмеженням кроку звуження $\le 3\text{ хв}$.

Також обчислюється згладжена баєсова оцінка базової ймовірності курсу на Франківськ:
$$P(\text{ІФ} \mid P) = \frac{\text{долетіли або збиті на шляху} + 1}{\text{усі цілі через } P + 2}$$

## 4. Команди CLI для оператора

Усі операції керуються через модуль `src.learning.cli`:

```bash
# 1. Початкова ініціалізація довідника v0001 з профілю міста (`data/profiles/<місто>.json`)
python3 -m src.learning.cli seed

# 2. Перегляд статусу (активна версія, кількість цілей, кандидати)
python3 -m src.learning.cli status

# 3. Перегляд нерозмічених цілей
python3 -m src.learning.cli unlabeled

# 4. Розмітка цілі (долетіла / збита / відвернула)
python3 -m src.learning.cli label T-2026-10-10-01 reached_target --arrived-at 2026-10-10T21:55:00+00:00
python3 -m src.learning.cli label T-2026-10-10-02 diverted --notes "пішов на Хмельницький"

# 5. Пошук нових форм назв у збережених постах
python3 -m src.learning.cli discover-aliases

# 6. Перегляд кандидатів у назви
python3 -m src.learning.cli aliases

# 7. Схвалення або відхилення кандидата
python3 -m src.learning.cli approve-alias "скалат" --new-point skalat --level 2
python3 -m src.learning.cli approve-alias "кам'янці" --point kamianets_podilskyi
python3 -m src.learning.cli reject-alias "невідоме_слово"

# 8. Запуск перенавчання (створює vNNNN зі статусом pending)
python3 -m src.learning.cli retrain

# 9. Перегляд різниці між поточною активною та новою версією
python3 -m src.learning.cli diff 2

# 10. Активація нової версії (або відкат)
python3 -m src.learning.cli promote 2
python3 -m src.learning.cli rollback

# 11. Очищення старих сирих постів (за замовчуванням старше 14 днів)
python3 -m src.learning.cli purge-posts --days 14
```

## 5. Тестування

Модульні тести реалізовані на синтетичних даних у `tests/test_learning.py`:
```bash
python3 -m unittest discover -s tests -t . -v
```
Покривають:
- Стійкість нормалізації та стемінгу українських топонімів.
- Версіонування, атомарні перемикання, гарячий кеш та відкат.
- Асиметричне калібрування ETA та баєсові частоти.
- Захист від оновлення під час активної атаки (`freeze`).
- Перевірку на `holdout` цілях перед активацією.
- Повний цикл виявлення та схвалення аліасів.
