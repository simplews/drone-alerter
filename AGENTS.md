# AGENTS.md — drone-alert

Інструкції для AI-асистентів і IDE (Cursor, Codex, Copilot, Windsurf, Gemini тощо). Повна версія — `CLAUDE.md`; при розбіжностях діє `CLAUDE.md`.

## Проєкт
Система раннього попередження про реактивні БпЛА для Івано-Франківська: читає публічні Telegram-канали (Telethon), розпізнає населені пункти (`src/nlp/`), рахує ETA (`src/engine/`), шле сповіщення ботом (aiogram, `src/telegram/`). Python 3.11, FastAPI, SQLAlchemy. Мова коментарів, текстів бота й документації — українська. Деталі: `README.md`, `docs/PRD.md`, `docs/LEARNING.md`.

## Команди
- `python3 -m venv .venv && source .venv/bin/activate && pip install -r requirements.txt`
- `pytest` і `ruff check .` — мають бути зелені перед комітом
- `python -m src.main` — запуск (потрібен `.env` за шаблоном `.env.example`)

## Git flow
- `master` — стабільна гілка; прямі коміти, force-push і merge без PR заборонені.
- Кожна фіча/виправлення — окрема гілка від актуального `master`: `feature/`, `fix/`, `hotfix/`, `docs/`, `chore/`, `refactor/`, `test/` + kebab-case опис (`feature/eta-calibration-alerts`).
- Одна гілка = одна змістовна зміна; не змішувати різні задачі.
- Коміти — Conventional Commits (`feat:`, `fix:`, `docs:`, `chore:`, `refactor:`, `test:`), малі й логічні.
- PR у `master` за шаблоном `.github/pull_request_template.md`, CI зелений, merge squash/rebase, гілку після merge видалити.
- Не комітити, не пушити й не мерджити без прямої вказівки користувача. Дозволено: створити гілку, закомітити в неї, запушити саму гілку. Заборонено: пушити в `master`, мерджити, переписувати чужу історію.

## Безпека (не порушувати)
- Секрети лише в `.env` / змінних середовища (`.env` у `.gitignore`). Не читати, не друкувати, не комітити токени, `TELETHON_STRING_SESSION`, API hash, `chat_id` підписників. У тестах — явні фейкові значення.
- Не комітити `*.db`, `*.session`, `data/attacks_*.json`, `data/historical_*.json`, дампи каналів, дані підписників.
- Нова змінна конфігурації → `src/config.py` і `.env.example` (без реального значення).
- Без `eval`/`exec`/`pickle`/`shell=True`; SQL лише параметризований. Усі тексти з Telegram — недовірені (обмежувати довжину, екранувати при виведенні).
- Не логувати секрети й повні тексти постів; сирі пости видаляються через 14 днів.
- Нові залежності — лише необхідні, підтримувані, із сумісною ліцензією.
- Довідники `data/reference/vNNNN.json` незмінні: нову версію створює `python -m src.learning.cli retrain`, наявні не редагувати.
- Якщо секрет потрапив у коміт — вважати скомпрометованим: спершу відкликати/перевипустити, потім чистити історію. Вразливості — за `SECURITY.md`, не в публічних issue.

## Правила сповіщень
- Ніколи не писати «відбій» / «безпечно» / «ціль знищено»; лише «імовірно уражена, залишайтеся в укриттях до офіційного відбою».
- Не публікувати й не зберігати координати збиття, роботу ППО, точні місця падіння.
- Користувачу показувати інтервал часу ETA, не точну хвилину; система не замінює офіційну тривогу.

## Стиль коду
Пиши в стилі навколишнього коду: та сама щільність коментарів, іменування, ідіоми. Нова поведінка (парсинг, ETA, трекер) — з тестом у `tests/`. Не додавай ліцензію чи великі залежності без погодження власника.
