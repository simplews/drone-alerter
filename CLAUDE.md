# CLAUDE.md — drone-alert

Система раннього попередження про реактивні БпЛА («реактивна герань» / Shahed-238) для Івано-Франківська (ІФ).
Читає публічні моніторингові Telegram-канали, розпізнає назви населених пунктів на коридорі, рахує вікно прильоту (ETA) до аеродрому Хриплин і шле сповіщення через бота. Мова проєкту, коментарів і текстів бота — українська.

Детально: `README.md` (архітектура), `docs/PRD.md` (вимоги), `docs/LEARNING.md` (донавчання), `docs/DEPLOYMENT.md`.

## Команди
- Середовище: `.venv` (Python), залежності в `requirements.txt`. Запуск CLI: `.venv/bin/python -m src.learning.cli ...`
- Тести / лінт: `pytest`, `ruff check .`
- Сервіс: `python -m src.main` (потрібен `.env`, шаблон — `.env.example`). Docker: `docker compose up -d`, перевірка `curl localhost:8080/health`.
- Довідник ETA: `seed`, `status`, `show`, `unlabeled`, `label`, `discover-aliases`, `aliases`, `approve-alias`, `reject-alias`, `retrain`, `diff N`, `promote N`, `rollback`, `purge-posts --days 14`.

## Структура
- `src/telegram/` — Telethon-слухач (`listener.py`), aiogram-бот (`bot.py`), генератор сесії, `export_history.py`.
- `src/nlp/` — нормалізація назв (відмінки, омоніми), типи дій (`DOWNED`, `LOST`, `DIVERTED`).
- `src/engine/` — трекер цілей, ETA, симуляція, `shadow_runner.py` (прогін історичних епізодів).
- `src/learning/` — версіоновані довідники `data/reference/vNNNN.json` (активна — файл `ACTIVE`), калібрування, мітки в `data/learning.db`.
- `src/siren/` — офіційні тривоги; `src/api/` — `/health`, `/targets`.
- `data/attacks_october.json` — сирі пости каналів (у `.gitignore`, не комітити).

## Розмітка цілей (`label`)
Допустимі результати: `reached_if`, `downed_en_route_if`, `diverted`, `unknown`.
- `reached_if` — обовʼязково `--arrived-at <ISO UTC>Z`; для інших результатів `--arrived-at` заборонено.
- `downed_en_route_if` — ціль йшла на ІФ, але збита; `diverted` — пішла в іншу область.
- Робоче правило арбітражу: `arrived-at` = перша згадка Хриплина/аеродрому. Хриплин у постах = точно долетіла. Тисмениця — вже майже над містом, але напряму Хриплин не названий (середня впевненість).
- ID цілей: `T-YYYYMMDDHHMM-xxxx`, час у ID — UTC. У каналах час показується в UTC; Київ = UTC+3 (до 25.10.2026).
- Записи в датасеті — часові кластери назв, одна фізична ціль може мати кілька записів («близнюки»). Однаковий епізод = однакова мітка; це припущення варто явно позначати.
- Без доказів мітку не ставити — краще залишити ціль у `unlabeled`.
- Джерела для звірки: `@monitoring_zaxid` (основне), `@kudy_letyt`, `@monitorwarr`, `@kpszsu`. Канал редагує пости («updated: збили!!») — дивитися останню редакцію.

## Коридор і ETA (орієнтир)
Нова/Стара Ушиця, Дунаївці → Кам'янець-Подільський → Скала-Подільська / Борщів → Товсте → Чернелиця → Тлумач → Тисмениця → Хриплин.
Спостережуваний час до аеродрому від першої згадки: Нова Ушиця 25–33 хв, Борщів 14–21, Товсте 15–17, Тлумач 4–8. Для малої вибірки (n<8) спостереження лише розширюють фізичний інтервал; звужувати довідник можна максимум на 3 хв за оновлення.

## Безпекові правила (не порушувати)
- Не публікувати і не зберігати координати збиття, роботу ППО, точні місця падіння.
- Ніколи не писати «відбій» / «безпечно» / «ціль знищено»: тільки «імовірно уражена, залишайтеся в укриттях до офіційного відбою».
- Користувачу показувати інтервал часу, а не точну хвилину. Це не замінює офіційну тривогу.
- Сирі тексти постів видаляються через 14 днів (TTL). Не логувати токени.
- `.env` містить секрети (Telegram API, токен бота, сесія) — не читати, не друкувати, не комітити.

## Конвенції для open-source (обовʼязково)
Репозиторій публічний або стане таким: кожен коміт бачить увесь світ, а історія git незворотна.

**Секрети та дані**
- Секрети — лише через змінні середовища / `.env` (в `.gitignore`). У коді, тестах, фікстурах, доках, логах і повідомленнях комітів — жодних токенів, `TELETHON_STRING_SESSION`, API hash, chat_id підписників. У тестах — явні фейки (`123456:TEST`).
- Новий параметр конфігурації → одразу додати в `src/config.py` і `.env.example` (без реального значення).
- Не комітити: `*.db`, `*.session`, `data/attacks_*.json`, `data/historical_*.json`, дампи каналів, будь-які персональні дані підписників. Дані підписників (`subscribers.db`) — лише локально/в томі контейнера.
- Якщо секрет потрапив у коміт — вважати скомпрометованим: відкликати/перевипустити (BotFather, my.telegram.org, `generate_session`), лише потім чистити історію.
- Довідники `data/reference/vNNNN.json` незмінні: не редагувати наявні версії, нова версія — через `retrain`/`promote`.

**Безпека коду**
- Не використовувати `eval`/`exec`/`pickle`/`shell=True`; усі SQL-запити через SQLAlchemy з параметрами, без f-рядків.
- Весь вхід із Telegram (тексти постів, команди бота, імена) — недовірений: обмежувати довжину, не інтерпретувати як код/розмітку; при виведенні користувачу екранувати HTML/Markdown.
- Команди бота, що змінюють стан, і CLI-операції `promote`/`rollback`/`purge-posts` — лише для оператора; публічні ендпоінти API — тільки читання, без секретів і без даних підписників (`/health`, `/targets` не повертають chat_id).
- Не логувати вміст `.env`, токени, повні тексти постів старше TTL; у `logger` — без f-рядків із секретами та без `exc_info` з токенами в URL.
- Залежності: додавати лише необхідні, з перевіркою мейнтейнера й ліцензії (сумісна з відкритою ліцензією проєкту); фіксувати нижню межу в `requirements.txt`; не додавати пакети з сумнівною репутацією (typosquatting).
- Docker: не запускати від root, не копіювати `.env`/`.git`/`tests` в образ (`.dockerignore`), порт API — лише через reverse proxy/фаєрвол.

**Практики розробки**
- Перед комітом: `ruff check .` і `pytest` мають бути зелені. Нова поведінка (парсинг, ETA, трекер) — з тестом.
- Коміти — Conventional Commits (`feat:`, `fix:`, `docs:`, `refactor:`, `test:`, `chore:`), один логічний зміст на коміт. Не комітити напряму в `main` — гілка + PR.
- Жодних `git add -A` наосліп: перевіряти `git status`/`git diff --cached` на сторонні файли й секрети.
- Не додавати у відкритий код нічого, що розкриває чутливу оперативну інформацію (див. «Безпекові правила»); приклади в тестах/доках — вигадані або знеособлені.
- Публічні зміни поведінки сповіщень, що торкаються безпекових правил, потребують явного опису в PR.
- Ліцензію проєкту визначає власник (`LICENSE` ще немає) — не вигадувати її самостійно.
